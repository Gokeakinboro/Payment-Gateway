**Goal:** each product (payment-gateway core, **invoicing**, **wallet/Paymula**, **checkout**, **virtual accounts**) should be **disconnectable / fixable / upgradable without affecting the whole gateway.**

## Current state (why it's not there yet)
- **Modular monolith, only half-modularized.** True self-contained modules today: `backend/src/modules/{invoicing, wallet, assistant}` (own routes/services/_shared + own DB tables `inv_*`/`mw_*`).
- **NOT modules:** checkout = loose `routes/checkout.js`; **virtual accounts** = spread across `services/{palmpayService,payinFinalize,feeEngine}` + `routes/{checkout,palmpay-webhook,merchants,reports}`; core (transactions/rails/merchants/settlements/payouts) = loose routes.
- **Zero runtime isolation:** ONE Express app + ONE pm2 process, ONE shared `PrismaClient`, ONE Postgres DB, all mounted in one `server.js`; shared middleware (auth) + services (email, compliance, rails, feeEngine).
- **Consequence:** a boot error in ANY module crashes the WHOLE app (evidenced 2026-07-01 — missing `interswitchService` require broke server load); every deploy reloads all of paylode-api; schema changes ripple via shared DB/prisma. So one product can't be upgraded/disconnected in isolation.

## Target (phased re-architecture)
- **P1 (cheap, high value):** finish modularizing — make **checkout**, **virtual-accounts**, and **core** proper modules with clear boundaries; add **per-module mount toggles / feature flags** (disable a product without ripping code); **guard each module mount in try/catch + per-module health** so one module's boot error can't crash the whole app.
- **P2:** enforce **DB boundaries per module** (namespacing already partly there: inv_*/mw_*); no cross-module table access; per-module migrations.
- **P3 (when scale/independence demands):** split into **independently deployable services** (invoicing, wallet, checkout, VA, core) behind an API gateway — separate pm2 apps/containers, shared auth as a service. This is what enables true "upgrade one, others untouched."
