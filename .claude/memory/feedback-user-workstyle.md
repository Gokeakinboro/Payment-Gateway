The user (Goke) **strongly prefers tasks started AND finished cleanly in one go**. He dislikes leaving tasks open or carrying many dependencies (stated explicitly 2026-06-16).

**Why:** he likes closure — open loops and half-done work create mental load and risk.

**How to apply:**
- Scope work into **complete, self-contained units**; finish + verify before moving on.
- Don't leave hooks/stubs dangling as "open tasks." If something genuinely depends on his decision or an external key, name it as *his* pending input (a clean boundary), not as my unfinished work.
- Deliver, deploy, verify, then report done — minimise things "to be continued."
